# Очередь issue: ИПР, тест, Telegram, ачивки

Код не пишем. Issue в GitHub, правка `CONTEXT.md` и дополнение ADR 0006 — по отдельной просьбе.

## Уже решено

- Подтверждение компетенции — только приёмка строки руководителем ([ADR 0006](docs/adr/0006-idp-assignment-acceptance.md)). Сдача теста — не вердикт. Руководитель может принять строку без сданного теста. Это правило предметной области: при заведении issue дописать ADR 0006, не оставлять его только в плане.
- Личная пометка не считается ни подтверждением, ни ачивкой.
- Карточка ИПР визуально как таблица образца, но только из уже существующих полей. «Цель» — название задания, не новая сущность и не целевая должность. Колонки: Цель, Узнать, Проверить, Срок. Колонки «что может помешать», «вовлечение других людей» и минуты не заводим. Подписи SMART под шапкой не переносим. На текущем `main` таблицы материалов компетенции нет. Пока её нет, «Узнать» — это текст строки. Ссылки компетенции попадают в ту же колонку только после того, как справочник материалов влит в `main`. В задание их не копируют.
- Тест живёт на задании справочника. У задания может остаться только текст «проверить». Вопрос — варианты с одним верным. В строку при добавлении копируется снимок: правка справочника открытый план не меняет. Строка, добавленная до появления теста, остаётся без теста. Пишут те, кто правит справочник заданий. Попыток сколько угодно, пока строку не приняли. После приёмки попыток нет. Сдан — все вопросы верно. Верные ответы в HTML клиента не попадают, проверка на сервере.
- Руководитель рядом с приёмкой видит только «сдан / не сдан» и число попыток. Выбранные ответы не показываем.
- Telegram: чат привязывает сам сотрудник кодом из кабинета. Код живёт 15 минут и сгорает после одного успешного ввода. Отвязать чат можно. `getUpdates` крутит тот же процесс, что и `npm run dev`, пока сервер поднят. Отдельного демона нет. Webhook на localhost не делаем. Раз в месяц сводка сотруднику и его руководителю: просроченные строки и строки со сроком в ближайшие 30 дней. Принятые и без даты не входят. Руководителю — только прямые люди. Неактивный сотрудник и заблокированный бот рассылку не получают. Токен — секрет в `.env.local`, пустое значение и плейсхолдер отклоняются так же, как `SESSION_SECRET`. Если сервер в этом месяце не поднимали, сводка уходит один раз при следующем запуске. Прошлые месяцы пачкой не догоняем. Месяц с ошибкой сети не считается отправленным.
- Ачивки не хранятся, а вычисляются по текущим приёмкам всех не отменённых ИПР сотрудника. «Первая принятая строка» — один раз на сотрудника. Сняли приёмку и условия больше нет — ачивка пропадает. Отменённый план в расчёт не входит. Очков нет. В кабинете видны только свои: первая принятая строка; компетенция подтверждена; все компетенции пула подтверждены, даже если период ещё идёт; ИПР выполнен.
- Печать и выгрузка в xlsx — не в этой очереди. Сообщение в Telegram в момент приёмки — тоже не в этой очереди.

## Глоссарий при заведении issue

В `CONTEXT.md` появятся тест задания, попытка, «сдан», ачивка, привязка чата. Определение **Строки ИПР** дополнится снимком теста. Это глоссарий, не схема таблиц. Дополнение ADR 0006: принять строку можно без сданного теста.

## Очередь issue

Каждый пункт — отдельный pull request. 2 после 1. 3–6 по порядку. 7–9 по порядку. Ачивки от теста и Telegram не зависят. Telegram от теста не зависит.

1. Таблица ИПР, только чтение. Шапка (сотрудник, период), группы по компетенциям, колонки Цель / Узнать / Проверить / Срок. Материалы компетенции в «Узнать» — только если справочник материалов уже в `main`. Иначе колонка — текст «узнать».
2. Правка и приёмка внутри таблицы. Форма строки раскрывается по требованию, не висит открытой. Ход сотрудника и приёмка — в строке таблицы, не отдельной колонкой образца. Узкий экран — горизонтальная прокрутка.
3. Тест в справочнике `/assignments`. Схема вопросов, редактор, проверка «минимум один вопрос и ровно один верный вариант». Скрытое задание сначала возвращают в справочник, потом правят — как название и тексты. Уже скопированный в план снимок эта правка не меняет.
4. Снимок теста в строку при добавлении задания. Старые строки без теста не догоняются. Вопросы и варианты снимка — отдельные таблицы, не JSON в `idp_items`. Правки `schema.ts`, `migrate.ts`, `upgrade-base.ts`.
5. Прохождение теста сотрудником. Попытки, проверка на сервере, после приёмки нельзя.
6. Итог теста у руководителя рядом с «Принять»: сдан или нет, число попыток.
7. Привязка чата. Токен, код в кабинете на 15 минут и на одно использование, polling внутри процесса сервера, отвязка. В e2e заглушка: порт 3100 в `api.telegram.org` не ходит. Раздел в `docs/engineering-decisions.md` про прокси и polling. `BOT_TOKEN` в `.env.example`.
8. Сборка сводки. Чистая функция без отправки. Проверка границ 30 дней, просрочки, только прямые подчинённые, без неактивных.
9. Расписание и отправка. Журнал с уникальностью «получатель + месяц». Ошибки сети и прокси не помечают месяц отправленным. У админа кнопка «Отправить сводку сейчас», иначе месяц не проверить ни руками, ни e2e.
10. Ачивки в кабинете. Расчёт и показ можно разделить на два PR, если расчёт окажется отдельным модулем. Пример теста в `seed` — к issue 3, не к ачивкам: иначе на чистой базе тест не увидеть.
